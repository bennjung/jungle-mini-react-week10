# Phase 1 테스트 케이스 초안

기준: `docs/p1_prd.md`, `resc/phase1.md`.
아래는 동작 기준의 테스트 명세다. 함수 인터페이스와 명령 데이터 형식 확정 후 실행 가능한 테스트로 옮긴다.

## 스냅샷과 매핑

| ID | 입력 / 동작 | 기대 결과 |
| --- | --- | --- |
| S01 | `<div class="box">hello</div>`를 스냅샷으로 변환 | 요소의 nodeType, tagName, 속성, 자식 텍스트 노드의 nodeType과 nodeValue가 보존된다. |
| S02 | 중첩 요소와 여러 텍스트 노드를 변환 | 부모·자식 구조와 childNodes 순서가 보존된다. |
| S03 | 매핑된 테스트 DOM으로 새 스냅샷 생성 | 기존 노드에 대응하는 실제 영역 DOM 참조를 찾을 수 있다. 테스트 영역 DOM을 실제 영역의 변경 대상으로 사용하지 않는다. |
| S04 | 새 스냅샷 생성 후 테스트 DOM의 속성·텍스트 수정 | 저장된 스냅샷의 비교용 데이터는 바뀌지 않는다. DOM 직접 참조와 스냅샷 데이터의 독립성을 구분한다. |
| S05 | 새로운 `data-*` 속성을 추가한 DOM 변환 | 속성별 전용 로직 추가 없이 해당 속성이 스냅샷에 포함된다. |

## Diff와 실제 DOM 반영

각 케이스에서 변경 명령의 대상이 실제 영역의 올바른 DOM 노드인지 확인한다.

| ID | 이전 → 다음 상태 | 기대 결과 |
| --- | --- | --- |
| D01 | 동일한 트리 → 동일한 트리 | diff는 빈 배열을 반환하고, applyPatch는 DOM을 변경하지 않는다. |
| D02 | `<p>A</p>` → `<p>B</p>` | 텍스트 update. p 요소와 기존 텍스트 노드의 객체 동일성을 유지하며 텍스트 값만 바뀐다. |
| D03 | 속성 추가·변경·삭제 | update 후 실제 DOM의 속성이 다음 상태와 일치한다. 대상 요소의 객체 동일성을 유지한다. |
| D04 | `<div>A</div>` → `<p>A</p>` | replace 후 해당 위치에 p가 존재하며 이전 div는 제거된다. 새 노드의 실제 DOM 참조와 매핑이 연결된다. |
| D05 | 자식 목록의 처음·중간·끝에 새 노드 삽입 | insert 후 자식 순서가 다음 상태와 일치한다. 기존 형제 노드는 유지되고 새 노드의 참조와 매핑이 연결된다. |
| D06 | 자식 목록의 처음·중간·끝 노드 제거 | remove 후 대상만 제거되고 다른 형제의 순서와 객체 동일성이 유지된다. 제거된 노드는 현재 매핑의 유효 대상으로 남지 않는다. |
| D07 | 식별 가능한 기존 형제 A, B, C → C, A, B | move 후 순서가 일치하며 이동한 C의 실제 DOM 객체가 유지된다. 노드 식별 규칙 확정 후 명령 유형을 검증한다. |
| D08 | 중첩된 자식 하나의 텍스트 변경 | 해당 텍스트만 변경하고 부모·형제·변경 없는 하위 트리는 교체하지 않는다. |
| D09 | 한 번의 Patch에 삽입·삭제·이동·수정 혼합 | 전체 적용 후 구조·속성·텍스트·순서가 다음 상태와 일치한다. 앞선 작업으로 위치가 바뀌어도 다른 대상을 수정하지 않는다. |
| D10 | 노드 삽입·교체 후 다음 Patch에서 그 노드를 수정 | 갱신된 참조와 매핑으로 실제 영역의 해당 노드를 정상 수정한다. |

## 핸들러와 이력

| ID | 입력 / 동작 | 기대 결과 |
| --- | --- | --- |
| H01 | 최초 페이지 로드 | 실제 영역에서 초기 VDOM을 생성하고 그 VDOM으로 테스트 영역을 렌더링한다. 최초 상태를 이력에서 조회할 수 있다. |
| H02 | 테스트 영역 수정 후 Patch 클릭 | get → createSnapshot → diff → applyPatch → set 순서로 처리한다. diff의 이전 상태는 get이 반환한 VDOM이다. 실제 영역과 저장된 현재 상태가 수정 결과를 반영한다. |
| H03 | 두 번 Patch 후 뒤로가기·앞으로가기 | 선택한 이력 상태로 실제 영역과 테스트 영역이 함께 변경된다. |
| H04 | 이력의 처음에서 뒤로가기 / 끝에서 앞으로가기 | 유효 범위 밖으로 이동하지 않고 화면과 현재 상태를 유지한다. |
| H05 | 뒤로가기 후 테스트 영역 수정 및 Patch | 제안 정책: 현재 위치 뒤의 이력을 제거하고 새 상태를 저장한다. 이후 앞으로가기로 폐기한 상태에 접근할 수 없다. |
| H06 | 여러 번 Patch 후 과거 상태 조회 | 이후 DOM 변경이나 매핑 갱신이 과거 스냅샷의 구조·속성·텍스트를 변경하지 않는다. |

## 실행 테스트 작성 전에 정할 사항

- PRD의 `diff(currentVDOM, nextVDOM)`에서 `currentVDOM`은 위에서 조회한 `curVdom`으로 통일해야 한다.
- VDOM 필드명 `tageName`은 `tagName`을 뜻하는지 확정한다. attributes 배열 원소의 구조도 정한다.
- Diff 명령의 operation, 데이터, 대상 참조, 부모 참조, 삽입 기준 형제 참조 형식을 정한다.
- 테스트 DOM과 기존 VDOM의 객체 매핑 방식, 새 노드와 이동한 노드의 식별 규칙을 정한다.
- 초기 스냅샷 생성처럼 이전 VDOM이 없는 경우의 createSnapshot 호출 계약을 정한다.
- 과거 스냅샷에 있는 실제 DOM 참조가 삭제·교체로 분리된 경우, 이력 복원 시 참조와 매핑을 어떻게 재연결할지 정한다.
- 변경 없는 Patch의 이력 추가 여부와 H05의 분기 이력 정책을 확정한다.
- 주석 노드와 입력 요소의 value·checked 등 DOM 속성 외 상태를 지원 범위에 포함할지 정한다.
